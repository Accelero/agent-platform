# Agent platform 0.9.0

Published on 2026-11-13 from `5ba5e78216fac0d9657eaf0d541d72513349b244` (tag `v0.9.0`). The
[release workflow](https://github.com/Accelero/agent-platform/actions/runs/43358083761)
ran all 13 suites on separate runners: 1483 tests passed, none skipped. The one
credentialed manual case is outside the gate. The publish job then passed the
`artifact` tests against the pushed digests. The
[GitHub Release](https://github.com/Accelero/agent-platform/releases/tag/v0.9.0)
contains the same chart package as GHCR.

This release moves every upstream application, base image and build tool to
its current release, and reorganizes the tests into component suites that gate
publication.

## Upgrade notes

- **Multica v0.8.2.** The first start runs 71 new native migrations, which cannot
  be undone. The backend, web and CLI images move to v0.8.2. The vendored server
  source is v0.8.2 with the maintenance fence reapplied. Upstream now guards the
  token and CLI-token routes itself. The auth-boundary patch keeps only the
  direct-handler backstop for listing, renewing and revoking tokens.
- **Hermes v0.23.1.** The managed terminal policy now binds routed profiles
  natively, so the terminal-scope patch is gone. The image installs PyYAML for the
  runtime adapters because Hermes no longer ships it.
- **Hindsight 1.2.1** with `hindsight-client` 1.2.1 and the Hermes catalog plugin
  1.2.4. Dashboard activation now installs the plugin's Python dependencies into
  the home from PyPI. The first activation on a volume downloads about 80 MB and
  adds about 770 MB; each further profile adds about 200 MB. The Hermes Pod needs
  outbound access for this, as it already does for model providers and web
  search. The chart does not restrict Hermes egress; a deployment that adds egress
  rules must allow `pypi.org` and `files.pythonhosted.org`. The chart no longer sets
  `HINDSIGHT_BANK_ID`, which Hindsight 1.x lets override every home's own bank.
- **PostgreSQL 18.** The tools image ships PostgreSQL 18 clients and the recovery
  descriptor requires `database_major: 18`. Recovery points of 0.8.0 and earlier
  are refused.
- **Optional services.** RabbitMQ 4.4 cannot open a 3.13 data directory directly;
  upgrade through 4.0 with all stable feature flags enabled, or start from an empty
  volume. Redis 8.8 uses Redis Ltd.'s RSALv2/SSPLv1/AGPLv3 licensing. SearXNG moves
  to a current build. Nginx for both gateways is 1.31.7.

## Images and tools

Go 1.27, Python 3.14 (trixie) for the manager, Ubuntu 26.04 for the worker and
platform tools, PostgreSQL 18.7 (trixie) for the tools image, Helm 4.3.1,
kubectl 1.37.2, flux 2.10.0, gh 2.104.0, the kubernetes Python client 37.0.1 (the
newest that installs beside boto3), boto3 1.44.2 and PyYAML 6.0.3. The GitHub
Actions run on Node 24.

## Tests and release workflow

Tests are organized by component and level (`<component>-<level>` suites plus the
global `e2e`), all run through pytest; see [testing](../testing.md). Version tags
run every suite on its own runner before the publish job starts. The publish job
reruns the `artifact` tests against the pushed image digests before publishing
the chart. Pull requests and pushes to `main` run static checks only. The one
credentialed real-model Hindsight case stays outside the gate (`--manual`).
