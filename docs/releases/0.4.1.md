## Privacy checks

The earlier historical audit covered inherited layers, source history, release
attachments and workflow artifacts. This incremental audit checked all 13 new
0.4.1 layers and every layer of the corrected agent-runtime and tools images:
15 distinct layers, 295,297,844 compressed bytes, 22,942 regular file entries and
832,051,957 bytes of file content. All five image configurations and their
provenance were checked again, comprising 11 deduplicated metadata objects.
Chart file contents were also checked.

No matches for the reviewed deployment credentials or personal prompt/seed
material were found in that scope. Comparison values remained in process memory.
Provenance contains no automatically captured GitHub event payload. Public
upstream software templates and test fixtures remain part of their pinned
dependencies. Existing Git author attribution has the maintainer's approval.

Unused build-generated OpenSSH host keys and an inherited snakeoil TLS private
key were removed from release layers. The former are deleted in the installation
RUN instruction; the tools image copies its cleaned filesystem into a scratch
stage. Inspection of every layer of these two replacement images and read-only
root container checks confirmed that the unused key files are absent.
Actual runtime host keys continue to be generated when an agent runtime starts.

Future release and cache builds retain the reviewed-context privacy gate in
`release-policy.json` and `agent_platform/privacy.py`. Private deployment settings,
identities, skills and memory enter through mounted runtime inputs.

## Functional checks

- All 49 platform tests, Ruff checks, privacy preflight and Helm lint passed.
- Hosted Checks, cache and release jobs for the release source passed.
- The actual downloaded chart renders six Deployments with digest-pinned images,
  native manager configuration and admission rules using consumer values, with
  no pull secrets.
- Three local Docker recovery tests passed against the published digests:
  encrypted S3 checkpoint/readback and database restoration, Multica migrations
  on PostgreSQL 17, and consumer administrator-module imports in tools.
- The published runtime-manager image passed its serialized execution handoff
  smoke test without network access.

These checks used disposable local services. Live Kubernetes rollout, owner
email login and a completed assistant task are separate deployment checks.
Anonymous package access is also checked separately from functional qualification.

## Retired images

After the replacement passed qualification, the affected agent-runtime 0.2.0,
0.3.0 and 0.4.0 versions and tools 0.4.0 were removed, including their platform
and provenance manifests: 12 GHCR version records in total. Both package identities,
0.4.1 manifests and their `latest` tags were verified intact. Historical Git tags
and release/chart records remain as provenance; their retired image dependencies
make older releases unavailable for deployment.
